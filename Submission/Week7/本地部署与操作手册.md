## 1. 开机与预检

在控制台核对实例ID后启动320。SSH主机和端口以控制台当次显示为准；历史连接示例仅是：

```bash
ssh -p 27493 root@connect.nmb2.seetacloud.com
```

只在正常密码提示或已受信任密钥中认证；不把密码放进命令、环境变量、仓库、日志或录像。不跳过主机密钥检查。

远端预检：

```bash
hostname
nvidia-smi --query-compute-apps=pid,used_memory --format=csv,noheader,nounits
ss -ltnp 'sport = :8000 or sport = :8001'
```

主机应为`autodl-container-be044ebe99-be706b14`。GPU或目标端口被占用时先查清所有者，不盲目kill。按模型manifest核对AWQ文件集与SHA-256，并核对上述依赖版本；单纯路径存在不足以证明身份。

## 5. 不完整回答与Stop判定

- 核心层对错模型、空回答、非`stop`和`length`仍严格失败。
- UI在已有可见部分文本时附加明确不完整标记并收尾，只为避免Gradio差量状态污染，不表示核心请求成功。
- Stop必须在生成中点击，并同时有界面停止和后端关闭证据；已自然结束后点击不算。
- 提交后首token到达前立即Stop仍是保留限制，不以生成中Stop的结果外推。

具体已验范围与保留限制见同目录优化记录.md。

## 6. 证据与清理

1. 保存原始录像、UI/服务审计、模型身份、参数、输入哈希和代码哈希；录像不显示密码、认证终端或无关窗口。
2. 回放检查录像可读性、实际流式和Stop时机，然后生成SHA-256清单。不剪掉失败后宣称全部通过。
3. 在终端A对本轮服务Ctrl-C，确认GPU无本轮进程且端口关闭；再停止终端C的UI和终端B的隧道。
4. 清除本轮临时认证材料，不删除模型、历史日志或用户数据。
5. 在控制台关闭320并确认“已关机”。服务停止不等于实例停止计费；关机也不免除数据盘费用。

常见错误：连接拒绝先查隧道和服务；400检查上下文/图片限制；404核对模型名；回答错误保留原图和收据，不自动改权重或图片预算。
