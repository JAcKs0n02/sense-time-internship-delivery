## 专业术语

| 术语 | 解释 |
|---|---|
| 周报 | 对一周任务、方法、数据、结果、失败和结论的结构化报告，不只是每日链接汇总 |
| 验收矩阵 | 将老师每一项要求映射到状态、指标和具体证据文件的表格 |
| Model archive | 模型文件或 adapter 的血缘、路径、大小、哈希、配置和加载验证集合 |
| Lineage | 从基座 revision、训练数据、代码/配置到最终模型的完整可追溯链 |
| Manifest | 机器可读的文件清单和元数据，用来证明归档与真实远端文件一致 |
| Adapter model | 只保存 LoRA 增量权重，需要配合指定基座模型加载 |
| Merged model | 将 adapter 合并进基座后的完整模型；体积更大，需另行做独立加载和哈希 |
| Evidence gate | 缺少原始日志、数量、哈希或验证结果时即不判定完成的证据门禁 |
| Descriptive result | 只描述固定小样本上的观察，不外推为所有场景的统计结论 |
| Teacher projection | 从完整工程归档复制老师实际需要的成果，而不是把整个仓库提交给老师 |

## 详细实施步骤

### 1. 执行跨日证据审计

逐日运行验证脚本，核对文件存在、数量、ID、schema、SHA、模型 revision、配置、return code 和非有限值。检查 Day 22 图片贯穿 Day 23–Day 25，Day 26 训练/评测隔离保持不变；任何不一致先回到来源日修正。

### 2. 冻结报告数据源

建立机器可读的报告输入 manifest，列出所有 CSV/JSON/JSONL、日志、热力图、模型清单和 SHA。报告中的表格和数字只从这些冻结文件生成，避免手工复制产生不一致。

### 3. 整理模型与素材血缘

记录 Qwen2-VL 官方仓库、不可变 revision、环境版本、五张图片来源/许可/SHA、processor 与生成配置。明确哪些资源在 Git、哪些留在 AutoDL、哪些因许可只提供 manifest。

### 4. 汇总图文推理与注意力

从 Day 23 生成 25 条完整结果表和按题型/图片类型的能力边界；从 Day 24 选择全部正式热力图，说明目标 token、层号、视觉 token 网格、head 聚合和限制。不能只展示最漂亮案例而隐藏正式失败案例。

### 5. 汇总幻觉与微调数据

报告固定 10 题的分子、分母、百分比和错误类型；说明样本量限制。汇总 Day 26 的 200 条训练数据、20 条隔离评测、任务分布、许可、污染检查和 schema 验证。

### 6. 汇总训练与效果对比

从原始日志生成训练 loss 等曲线或表格，说明 `freeze_vision_tower: true` 和可训练参数验证。展示 Base/LoRA 相同 20 条评测的五维加权均分、逐题胜负和幻觉率；明确三项门槛是否同时通过，不用 train loss 代替回答质量。

### 7. 撰写第 5 周报告

《第 5 周：多模态实践报告》固定章节为：

```text
1. 摘要
2. 老师要求与完成范围
3. 模型、环境与图片素材
4. 25 条图文推理结果
5. 跨模态注意力方法与热力图
6. 十题视觉幻觉检测
7. 200 条数据与 VLM LoRA 训练
8. Base/LoRA 隔离评测
9. 老师验收矩阵
10. 失败、限制与后续改进
11. 最终模型归档与复现入口
```

摘要和结论必须与硬门槛一致；任何未通过项不得用“基本完成”“总体良好”等模糊措辞伪装通过。

### 8. 建立老师四项验收矩阵

矩阵固定包含：

| 老师验收项 | 判定依据 |
|---|---|

### 9. 归档最终 VLM 模型

先决定最终交接是 Base+adapter 还是另有通过独立加载的 merged 模型。模型 manifest 保存：模型类型、远端路径、基座 repository/revision、训练数据 SHA、配置 SHA、代码 revision、逐文件相对路径/大小/SHA、总大小、加载 smoke、20 条评测摘要和生成时间。

在新进程中使用 `local_files_only=True` 做独立加载与一条新 smoke。只有 manifest 与远端真实文件一致，才标记最终模型可交接。

### 10. 创建精简教师提交

只有相应 Day 证据通过后才创建 `Submission/Week5/`。教师目录按 Day 22–Day 27 分区，包含老师直接要求的表格、图片、报告、配置/日志摘要和模型归档元数据；不复制整个仓库、7B 权重、checkpoint、缓存、账号、SSH 信息、私有盲评映射或 AutoDL 关机证据。

### 11. 验证教师包

检查相对链接、文件清单、敏感信息、空文件、图片可打开、CSV/JSON 可解析、教师要求覆盖和 ZIP 内容。教师报告中的每个指标必须与工程证据一致，不能只验证文件存在。

### 12. 更新状态并关闭资源

全部硬门槛通过后才能把 Week 5 和 Day 27 标记完成；未通过时保留真实状态与修复清单。若本日使用 AutoDL，证据同步与远端模型清单复核后关机，关机证明保留内部而不提交老师。

## 故障处理

- **跨日哈希不一致**：从最早变化的来源日重新冻结版本，并使所有受影响下游结果失效；不手工改 manifest 迁就旧结果。
- **报告数字与 CSV 不一致**：以冻结原始数据重新运行生成脚本；不手工修改报告数字或原 CSV。
- **热力图无法复现**：检查数组、元数据、图像 SHA 和绘图配置；不能只保留 PNG 截图作为唯一证据。
- **明显提升未通过**：周报和验收矩阵如实记为 `FAIL`，回到 Day 26 纠偏；不以 loss 下降或 adapter 可加载替代。
- **模型路径变化**：重新解析明确目标目录，重建 manifest 和加载 smoke；不能用模糊目录搜索自动选“最新模型”。
- **教师包过大**：移除模型权重、缓存和冗余工程文件，只保留老师要求成果与可验证 manifest；不牺牲关键表格和报告证据。
- **发现敏感信息**：停止打包，清理教师投影并重新运行递归扫描；不要通过隐藏文件名掩盖内容。
