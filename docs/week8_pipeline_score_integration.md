# Week8 主控评分恢复入口

主控现支持显式`--score-only`分支，在数据准备之前分流到已冻结的Gemini评分恢复流程。它复用原基座、SFT、DPO的既有回答与评分协议，不运行训练、OpenCompass或GPU生成。旧fresh入口仍保留原运行锁规则，不会静默切换裁判。

## 离线核验已完成成绩

```bash
bash run_pipeline.sh --score-only all --run-dir logs/score-audit-001
```

也可将`all`换成`original_base`、`final_sft`或`final_dpo`。每次核验使用新的报告目录。该命令无需密钥；检查冻结计划SHA256、回答来源与模型身份、代码和校准依赖，再逐题检查请求标记、原始响应、五维评分、加权汇总及token用量。新报告写入`score_recovery.json`，不改动历史成绩或防重复调用记录。缺少原始响应、被篡改的分数、失败或未完成状态不能通过。

这属于“已有真实评分的离线复核”，不是此次新推理、新评分或人工评分。三模型AI均分仍为3.9775、3.8275、3.8700。

## 显式恢复执行

```bash
bash run_pipeline.sh --score-only final_sft --execute-score --run-dir logs/score-resume-001
```

`--execute-score`仅允许单个模型。完整成绩直接独立核验，零新调用；未完成的执行仍使用已有评分器、固定输出目录和同一claim，保留独占锁、请求前持久化标记、原始响应验证及无自动重试规则。`FAILED_NO_RETRY`、未知是否已付费的请求、来源或协议变化仍须拒绝，不能通过新报告目录绕过。

真正需要新请求时使用此前已配置的Gemini凭据。当前三模型已经完成，无需重新收费评分。本轮只实跑了离线核验和完整成绩的零调用执行路径；中断、重复请求与失败保护由已有评分器回归测试验证，没有人为制造新的在线收费失败。

`--score-only`不能与`--quick`、`--skip-train`、`--skip-eval`或`--deploy`组合；`--execute-score`不能单独使用，也不能对`all`批量执行。报告不能写入受保护的原始评分、回答来源、校准或claim目录。

## 本轮验证

新增入口测试覆盖真实三模型复核、分流后不生成data/training目录、冲突参数拒绝、完整成绩不进入收费执行器、篡改评分与缺失响应拒绝、错误发布哈希拒绝及报告路径保护。

在不安装pip和第三方包的独立Python环境中，通过主控实跑三模型离线核验和SFT完整成绩执行路径，均为零新API调用；203个原评分和claim文件哈希保持不变。首次扩大回归使用系统Python，因缺少PyYAML导致训练相关测试失败；改用已有含PyYAML的环境重跑，最终39项相关测试全部通过，结果见`reports/week8/phase4_pipeline_score_integration/regression_green.log`。不将该环境问题计作评分入口成功，也不隐藏首次失败日志。

本轮没有启动320、没有读取密钥、没有新裁判请求。没有改写已经冻结的评分适配器或发布计划。此功能整合了“已生成回答→评分恢复/核验”这一分段，不代表新数据准备、训练、评估、部署已在单个干净CUDA环境一次跑通。下一步是把最新蒸馏、部署及本轮主控实测纳入综合报告并重新生成Word/PDF。
