# Week6 Agent 正式训练与评测方案设计

## 目标

建立一套可复现、输入自洽、能够同时衡量模型能力与 Agent 系统可靠性的 Week6 正式实验链路。最终教师提交包只呈现正式训练数据、正式评测、主实验模型、Prompt 消融和最终结论。

## 实验口径

- 老师要求的 100 条 ReAct 数据作为 `tool_sft_train_core_100.json` 单独归档。
- 正式训练可使用核心数据与扩展数据组成的训练集，但必须在 manifest 中分别记录数量和哈希。
- 开发集用于 checkpoint 和 Prompt 选择；最终测试集在模型、Prompt、生成参数与运行器全部冻结后执行。
- 已有实验结果作为历史版本证据保留，不覆盖原始字节；正式结果使用新的文件名、schema 版本和 SHA-256。
- 原始 ReAct 模型评测与带参数保护的 Agent 系统评测分别报告，不能用运行器保护掩盖模型能力。

## 数据设计

### 核心训练集

核心 100 条保持五类分布：Calculator 20、KnowledgeRetrieval 20、CodeExecutor 20、Knowledge+Calculator 25、Recovery/Termination 15。每类使用多种自然语言表达，不使用可被模型当作类别标签的连续编号前缀。

所有恢复类任务必须在用户输入中明确提供表达式、查询词或源码。多步任务必须覆盖零运费、非零运费、低于预算、等于预算和高于预算。源码任务覆盖换行、缩进、引号、等号、语法错误和风险节点。

### 扩展训练集

扩展集用于增加措辞、实体和边界条件覆盖。扩展集与核心 100 条分别存储，正式合并训练文件由确定性构建脚本生成。每条 Observation 只能由本地真实工具执行产生。

### 开发集与最终测试集

- 每条题目都必须自包含完成任务所需的全部输入。
- 数据生成器必须验证预期工具参数的标量值出现在用户输入中，或者能由前一步真实 Observation 唯一推导。
- 开发集与最终测试集的 ID、用户 Prompt 和语义工具案例均不得与训练集重合。
- 最终测试集不参与 Prompt 编写、checkpoint 选择或超参数决策。

## 评分契约

评分器输出以下独立指标：

1. 首工具选择；
2. 完整工具序列；
3. 工具参数 schema；
4. 工具参数精确性；
5. Observation 完整性；
6. 最终回答与 Observation 的一致性；
7. 业务语义正确性；
8. 安全终止；
9. 无重复调用；
10. 严格任务成功。

Calculator 任务比较数值；商品预算任务比较商品价、运费、总价、预算关系和差额；代码任务比较语法状态、错误码和风险节点；恢复任务比较错误状态、错误码和终止步骤。评分使用结构化谓词，不要求最终自然语言逐字一致。

不完整工具 JSON、残留 `<tool_call>` 文本、缺失终态回答和与 Observation 冲突的结论均不得计为成功。

## Agent 运行边界

Agent 继续通过 `create_react_agent` 绑定三个正式工具。运行器增加与业务数据无关的通用校验：

- 工具参数必须通过 schema；
- 商品预算任务在成功检索后必须调用 Calculator；
- Calculator 表达式的金额必须来自最新检索 Observation；
- CodeExecutor 的源码必须与用户提供的代码块一致；
- 工具调用格式不完整时最多允许一次结构化重试；
- `rejected`、`not_found`、`ambiguous` 或 `error` 状态后终止；
- 最大步骤、运行时限和重复 action/input 保护继续生效。

原始模型评测关闭参数保护，仅保留安全上限；系统评测启用完整保护。两套结果使用不同的运行模式字段。

## 训练与模型选择

训练与推理使用同一套固定版本：LLaMA-Factory 0.9.3、Transformers 4.52.4、PEFT 0.15.2、Torch 2.1.2+cu121。正式配置以 4-bit NF4 QLoRA、有效 batch 8、学习率 5e-5、LoRA dropout 0.05 和 2 epoch 为主方案。

训练中按固定步数保存 checkpoint。每个 checkpoint 在开发集上执行相同的确定性 Agent 评测，按严格任务成功率、参数精确率、完整序列准确率的优先级选择。训练 loss 只用于诊断，不作为最终模型选择指标。

## Prompt 消融

Prompt v1 是主实验起点。每轮消融只改变一条规则，并保持模型、数据、生成参数和工具代码不变。最终测试集只运行开发集上选出的 Prompt。未入选版本作为消融记录，不作为最终部署配置。

## 验收门槛

- 首工具选择不低于 95%；
- 完整工具序列不低于 90%；
- 参数精确率不低于 95%；
- 业务语义成功率不低于 90%；
- Observation 完整性为 100%；
- 无重复循环为 100%；
- 最终回答忠实率不低于 95%。

30 条以内的结果只作开发诊断。正式最终测试集应至少 100 条，使单题权重不高于 1 个百分点。
