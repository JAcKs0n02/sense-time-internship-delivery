# Week5 Day26 V7 纠偏设计

## 1. 目标与交付边界

本轮的目标不是把 v6 的 `FAIL` 改成文字上的 `PASS`，而是在不接触旧最终集进行调参的前提下，重新建立可信的数据、训练和评测链路，训练一个真正改善的 VLM LoRA，并只在候选模型冻结后使用一次全新的最终集。

Day26 教师交付仍严格对应：

- 基座模型与 LoRA 的定量对比；
- 幻觉率评估；
- LoRA 权重与可复现的训练、评测证据；
- 结果达到预注册门槛后才更新 `Submission/Week5/Day26_VLM_LoRA`。

v6 保留为内部失败基线，不作为下一次教师最终交付。

## 2. 已确认的失败根因

### 2.1 v6 不是整体无效，而是能力分化严重

v6 最终结果为 Base 3.7825、LoRA 3.7950、平均提升 0.0125，LoRA 赢 12/20，幻觉率从 65% 降到 55%。它满足部分指标，但没有达到预注册的平均提升 `>= 0.50`，所以综合判定必须是 `FAIL`。

分类和模式分析显示：

- 图表与 UI 类有提升；
- 公式、OCR 和自然场景发生退化；
- correction 模式平均提升约 0.215；
- direct 模式平均下降约 0.190。

这说明模型学会了更强的“否定/纠错模板”，却损失了直接回答的完整性与精确转录能力。

### 2.2 训练分布人为强化了单向否定

v6 的 300 条加权训练记录由 200 条唯一记录扩展而来，其中 direct 与 correction 被重复。所有 50 条 correction 样本都来自错误陈述，目标答案全部是“不符合”。重复后 correction 占训练集三分之一，且没有任何“陈述正确，应当确认”的反例。

因此，模型把 correction 学成了固定拒绝模式，而不是依据图像验证陈述真伪。这与 correction 提升、direct 退化的实测现象一致。

### 2.3 部分公式和 OCR 标签存在事实错误或不可判定性

人工视觉复核确认训练集中至少存在以下问题：

- `formula-01` 的标签多写了前导负号；
- `formula-02` 的标签把图中符号系数改成了具体数值；
- `formula-04` 的标签与图中实际公式含义不一致；
- 其他手写公式也存在无法从像素可靠确认的转录内容。

旧最终集同样存在不适合作为金标准的样例：

- `ocr-14` 的图片确实是英文印刷体票据，但验证声明被错误标注为不符合；
- `formula-13` 和 `formula-14` 的手写内容具有歧义，参考答案却给出过度确定的精确式子；
- `ocr-13` 是多图拼贴，LoRA 出现“2.33”重复输出，暴露出训练模板和解码稳定性问题。

### 2.4 旧评测协议已经失去最终集资格

旧 final 已运行至少两次，且其提示词模板与训练集存在完全重复。它可以继续用于失败分析，但不能再用于模型选择或下一轮最终结论。旧 Base 输出在不同轮次间也发生明显变化，说明旧结果未充分绑定生成配置与运行血缘。

## 3. 方案比较

### 方案一：只调低学习率或 LoRA scale

成本最低，但无法修复错误标签、单向 correction、提示词污染和旧最终集失效。它最多缓解过拟合，不能建立可信交付。

### 方案二：保留训练数据，仅替换最终集

能够避免继续使用暴露的 final，但训练数据中的错误公式和“一律否定”仍会直接影响模型。即使得到正向分数，也无法证明提升来自可靠学习。

### 方案三：重建标签合同、训练集与新评测集

本轮采用此方案。它成本最高，但能同时解决数据事实性、模式平衡、训练/评测隔离和运行可复现性，是唯一适合正式交付的路线。

## 4. V7 数据合同

### 4.1 数据规模与划分

- train：50 张图片，每张 4 条任务，共 200 条唯一训练记录；
- dev：10 张图片，每张 2 条任务，共 20 条记录；
- final：10 张图片，每张 2 条任务，共 20 条记录；
- 五类任务保持平衡：自然场景、OCR、公式、图表/表格、UI；
- train、dev、final 的图片 SHA256 必须完全不重叠；
- 不再用简单复制扩展训练权重。

### 4.2 每张图片的人工事实卡

事实卡必须至少包含：

- 唯一图片 ID、split、category、相对路径和 SHA256；
- 来源页面、直接下载地址、作者、许可证和许可证地址；
- 至少 3 条可直接观察事实；
- OCR/公式类的精确转录字段；
- 无法确认之处和不确定性说明；
- 一条可验证陈述及 `claim_supported` 布尔标签；
- 人工复核状态。

任何看不清或有歧义的字符不得被包装成确定金标准；这类样例应改为描述可见结构，或从训练/评测集中剔除。

### 4.3 四种训练任务

每张 train 图片构造以下四种互补任务：

1. `direct`：直接回答图片中的主要内容，强调完整、具体、不臆测；
2. `evidence`：按类别提取关键视觉证据，要求答案可由像素验证；
3. `verification`：判断给定陈述是否符合图片，并指出支持或反驳证据；
4. `grounding`：区分可确认内容与不确定内容，显式约束幻觉。

`verification` 必须在每个 split、每个 category 内保持支持/不支持平衡。train 中每类 10 张图片对应 5 条 supported 和 5 条 unsupported；dev/final 中每类两张图片各一条 supported 和 unsupported。

### 4.4 文本多样性

- train、dev、final 不允许完整 `user_instruction` 重复；
- 三个 split 使用不同的问法模板，并进行类别化改写；
- 禁止所有答案复用统一的长段落骨架；
- validator 对 n-gram 或标准化文本的高重复率进行告警或阻断。

## 5. 图片来源与许可

优先使用可追溯的官方开源仓库图片，并固定仓库 revision。候选来源包括：

- scikit-image，BSD-3-Clause；
- PaddleOCR，Apache-2.0；
- Pix2Text，MIT；
- OmniParser，CC-BY-4.0。

许可与像素质量合格的旧 train 图片可以在废弃旧标签后重新进行双重复核；旧 dev/final 图片不得进入 v7 的任何 split。新增 dev/final 图片必须先下载原始字节、计算 SHA256、记录来源和许可，再进入人工标注。训练与评测不得依赖搜索结果缩略图或无法回溯的二次转载。

## 6. 候选训练矩阵

所有候选使用同一 Qwen2-VL-7B-Instruct 基座、同一 200 条 v7 训练集、冻结视觉塔与 projector，并只在 dev 上比较。

| 候选 | Rank/Alpha | 学习率 | Epoch | 目的 |
|---|---:|---:|---:|---|
| A | 16/32 | 1e-5 | 1.0 | 推荐默认，降低灾难性遗忘 |
| B | 16/32 | 2e-5 | 1.0 | 判断学习率是否不足 |
| C | 16/32 | 1e-5 | 1.5 | 仅在 A 欠拟合时增加训练量 |

候选生成后，仅在 dev 测试 LoRA scale 0.75、0.85、1.0。除表中单变量外，其余训练和生成参数固定。

## 7. 评测隔离与门槛

### 7.1 开发集门槛

候选进入 final 前必须同时满足：

- dev 平均加权分提升 `>= 0.35`；
- direct 模式平均分不下降；
- LoRA 至少赢 12/20；
- 幻觉率不高于 Base。

未通过时只允许回到训练数据或候选矩阵，不得查看新 final 输出。

### 7.2 最终集门槛

候选模型、LoRA scale、生成参数和评分规则冻结后，才解封并运行一次新 final。最终 `PASS` 必须同时满足：

- 平均加权分提升 `>= 0.50`；
- LoRA 至少赢 12/20；
- 幻觉率不高于 Base；
- 所有工程与血缘检查通过。

若新 final 失败，该结果必须如实归档；不得使用它继续选 checkpoint、scale 或修改答案。下一次训练必须配套另一套从未运行的最终集。

## 8. 运行血缘与防混跑

每次训练和评测运行都必须绑定：

- base revision；
- adapter 权重文件 SHA256，而不仅是 `adapter_config.json`；
- 训练数据、事实卡、图片 manifest 和训练配置 SHA256；
- cases、generation config、scoring config 的 SHA256；
- run ID、阶段（dev/final）和创建时间。

`--resume` 只能在上述指纹全部一致时继续；任一指纹变化必须新建 run，防止把不同 adapter、scale 或评测配置的记录混在一起。

## 9. Submission 更新规则

在 v7 最终门槛全部通过前，不替换教师 Submission。通过后只提交老师需要的内容：

- Day26 说明与数据/训练/评测摘要；
- 可信的 Base/LoRA 对比结果与幻觉率结论；
- 模型归档或明确的权重获取与校验信息；
- 图片来源、许可证和关键哈希；
- 可复现脚本和校验结果。

Submission 不包含 AutoDL 关机证据、登录信息、私有盲评映射或整个仓库。
