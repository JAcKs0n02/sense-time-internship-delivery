# 第8周全链路自动化设计

依据：2026-09-14 更新的《实习需求》Day40–45；源文件哈希见 reports/week8/requirements_source.json。用户已要求完成仓库内工作，本设计记录该授权范围内的实现选择。

采用增量模块化：历史 deliverables/ 与 Submission/ 保留可追溯实验，根目录新增 scripts/、configs/、data/、models/、logs/、reports/ 与 run_pipeline.sh。第7周仅移入最终提交版本代码及报告，不合并含探索状态的整个工作区。

数据阶段复用 Day7 清洗、精确及模糊去重代码，固定 seed=42，按问题分组后9:1划分，双格式使用相同样本ID。正式模式使用真实 tokenizer；quick 使用显式标识的字符测试 tokenizer，仅验收本地接口。

训练阶段加载 Week3 epoch-e5 与 Week4 corrective 配置，重写路径，依次 SFT→合并→DPO→合并。仅对OOM有限重试，独立attempt目录并保留失败日志；batch已经为1则失败退出，不暗改长度或epoch。

评估提供历史证据复算模式和真实模型模式。真实模式运行 OpenCompass 及20题生成，五维评分使用独立裁判API和固定rubric，验证数值范围、完整性并保留依据；自动评分不称人工盲评。历史模式清楚标记，不宣称本次模型推理。

部署复用第7周最终服务/UI代码，监督子进程、检查端口及服务模型身份、失败清理本次子进程。单卡默认文字服务；视觉按既有手册切换。

蒸馏使用教师生成的序列级目标，再训练0.5B学生2轮，规避同卡同时加载教师学生的显存问题；不声称实现软标签KL。配置、生成、训练、对比入口齐备；未执行的GPU实验保留pending。

报告以既有实验证据撰写八章，标注第2/5周质量失败、第7周工具偏差及第8周未实测项目。仓库规范化不删除用户历史权重或探索记录，不自动向教师发送材料。
