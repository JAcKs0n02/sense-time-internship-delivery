# 仓库结构

[项目首页](../README.md) · [逐项交付清单](DELIVERY_CONTENTS.md)

| 目录 | 内容 |
|---|---|
| `data/` | 正式SFT输入、隔离评估题、tokenizer、清洗后数据、公开基准、三模型最终答案 |
| `scripts/` | 数据准备、训练合并、评估、部署、蒸馏及报告生成入口 |
| `configs/` | 数据协议、训练与蒸馏配置、环境依赖 |
| `models/` | 最终模型角色、血缘与外部权重清单 |
| `logs/week8/training/` | 最终SFT/DPO的训练状态、日志与合并记录 |
| `reports/` | 综合技术报告、周报入口、图表和最终实验结果 |
| `Submission/Week1–8/` | 按任务日整理的正式实验材料与周报 |
| `deliverables/week1–7/` | 各周独立实验的源代码、配置、数据和实验记录；保持已有脚本及报告引用的相对路径 |
| `docs/` | 交付清单、运行说明、方法和结果说明 |
| `tests/` | 现行流水线、数据、评分、蒸馏和部署的回归测试 |

## 正式结果与工程档案

本目录为正式提交版。恢复工作树、临时输出目录、重复发布整包、GPU排队监控、失败会话编排、未采用的裁判试验及过期执行计划不在当前提交树中。完整开发过程保存在原始工程，原模型及中间检查点未删除。

完整基准输出位于 `reports/week8/benchmarks/`。部分最终证据沿用原有日期或阶段名称，以保持已定稿报告中的引用；这些目录只保存被引用的结果或当前核验所需文件，不代表尚有同名阶段待执行。

## 迁移与实验身份

`data/input_paths.json` 将冻结协议中的历史输入名称映射到 `data/week8/` 的实际位置。原始数据内容、协议字节、训练/验证划分不变；实际读取后仍检查协议中固定的SHA256。历史路径作为来源标识保存，不要求恢复工作树或临时目录存在。

已完成评估的回执绑定当时的代码版本。`reports/week8/reproduction/`保存核验该回执必需的旧代码字节和路径映射；核验只读取这些文件，不执行旧代码。现行代码由根目录 `RELEASE_SHA256SUMS.txt` 单独覆盖。

综合报告的Markdown、LaTeX、PDF、源文件包和图表保持原字节。整理仓库不改写实验成绩或将历史实测替换成本次CPU检查。
