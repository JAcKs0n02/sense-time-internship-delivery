# Week8 裁判第三轮：严格校验与有界重试

## 本轮修改

独立适配器 scripts/week8_deepseek_judge.py 现在要求恰好五个维度，每维恰好 score 和 reason，拒绝重复JSON键、多余字段、缺失字段、错误类型、非有限或越界分数、空理由。没有补括号、补引号或删除字段后重新解释原始结果。

新增 call_bounded：同一个案例最多两次请求，只有已经收到且模型身份与用量正常、评分JSON或结构不合格时才重试一次。题目、答案、提示词、参数保持相同，不根据分数高低重试。身份不符、用量异常、截断、HTTP错误或网络状态不明均不自动重试。调用者可在每次调用前检查预算。

每次调用前写开始标记，响应先落盘并fsync后才能重试；请求目录已存在时拒绝再次运行，避免重启导致重复消费。网络错误仅记录异常类型，不保存可能含敏感内容的异常消息。失败和成功响应均保留，用量累计所有有完整用量的尝试；用量缺失不会假装完整。

重试属于恢复机制，不能保证服务一定返回正确格式。重复失败仍拒绝该案例并停止本轮在线运行。

## 验证设计

先增加失败测试：上一轮V2-12多余字段未被拒绝、重复键及嵌套额外字段被忽略、有界审计执行器尚不存在。红色日志保存了这些失败，再实现修复。测试使用真实历史响应，通过替换网络调用实现离线回放，其余校验、落盘、累计与停止逻辑均真实执行。

本轮6个在线案例覆盖漏答、错误概率推导、正确代码、两次相同干扰指令及正确概率推导；最多12次请求。计划、题目、提示词、代码和rubric在调用前固定哈希。沿用第二轮的维度边界，补充明确JSON格式说明，并将无危险操作或泄密的评分干扰限定在安全性2至3分。本轮同时变更工程处理和提示词，不能用结果单独归因某一修改。

这一操作口径是项目对自动评分的解释，不是老师逐字指定；既有人工评分rubric、历史记录和正式20题均未改动。

证据保存在 reports/week8/phase2_judge_calibration_v3/。密钥不进入仓库；未启动GPU，未运行正式模型评分。
