# Week8 学生蒸馏前后评估

2026-09-18，320上的完整前后比较已完成，243份证据已回传并通过本地逐题重计分，实例已确认关机。结论：本次蒸馏流程可行，但没有获得CEval提升或有说服力的速度收益。

## 比较对象和固定口径

原始 Qwen2.5-0.5B-Instruct 与完成两轮训练的蒸馏0.5B，均在同一320实例、单卡RTX3090、BF16条件下运行。不是将7B教师与0.5B学生的体量差异计作蒸馏加速。

- CEval：固定52科、val共1346题、dev前5题示例，生成式答题；最大上下文2048、最大输出32、batch1、greedy。按冻结标准答案逐题核对，汇总使用总正确数/1346。
- 速度：固定12条提示，2次预热、10次正式计时，每次恰好128个新token；计时包含prefill，前后CUDA synchronize。吞吐为1280/十次总秒数，同时记录单次耗时中位数。
- 不调用外部裁判API，不使用旧实验成绩替代此次推理。

## tokenizer兼容处理

导出时 tokenizer 发生序列化格式变化，tokenizer_config新增空的extra_special_tokens与padding_side=left；简单比较文件哈希会拒绝配对。用Transformers4.50.0对原tokenizer执行save_pretrained，得到的tokenizer.json、merges.txt、vocab.json、added_tokens.json、special_tokens_map.json与真实导出对应文件逐项哈希一致。

远端继续比较实际两个tokenizer的完整vocab、backend配置、special_tokens_map及chat_template；然后通过真实OpenCompass loader/retriever/chat wrapper检查全部1346题，要求原始与导出tokenizer的token序列相同，并与已有冻结prompt哈希相同；12条速度提示亦须相同。该预检已在本会话通过，最大输入1361token，无截断。

评估使用新目录中的两个独立模型视图：各自保留对应权重和model config，统一使用原始学生的tokenizer及generation_config。权重通过硬链接保持字节不变，分别按原始模型清单和训练合并回执绑定。不修改原始模型目录，也不修改真实蒸馏导出。batch1不涉及不同样本之间的padding差异。

|---|---:|---:|---:|
| CEval正确题数 | 723/1346 | 715/1346 | -8题 |

## 效果分析

1. **CEval小幅下降是真实答案差异。**707题两组都正确，615题两组都错误，8题由错变对，16题由对变错。最终选项发生变化的题目共47道，包含23道由一种错误答案变为另一种错误答案。
2. **未见“蒸馏后格式更差导致降分”的证据。**原始模型1343条、蒸馏模型1345条直接给出单一A/B/C/D选项；按冻结解析器，无法解析为A/B/C/D的回答分别为1条和0条。原始回答、本地独立选项提取、OpenCompass评分明细、冻结标准答案逐题核对一致。没有为了提高分数更换解析规则。
3. **训练损失下降不能替代CEval。**本次仅137条训练、15条验证、2轮，采用教师生成文本监督；数据规模及通用指令任务与CEval专业知识问答的匹配有限，可能限制迁移收益。该解释是合理假设，不是经消融证明的因果结论；现有证据也不足以把下降确定归因于过拟合。
4. **不将教师体量差异冒充蒸馏收益。**这里比较的是0.5B学生训练前后，不是7B教师与0.5B学生，因此本次不能报告“蒸馏使推理加速若干倍”。

本次可登记为“成功完成蒸馏尝试，效果不理想并已有分析”。老师Day42.3要求比较CEval及推理速度，验收项❹明确写有“即便效果不理想，需有分析”（见requirements_snapshot.txt，对应源DOCX/PDF哈希本轮再次核对一致）。不据此把蒸馏模型提升为优于原始学生的发布候选，也不为追求正向数字自动追加训练。
