# Week8 校准裁判接入正式评估入口

## 已完成的行为变更

step3_eval.py 的 fresh 模式已替换旧通用裁判调用路径，使用第三轮校准提示词及参数、严格评分JSON校验、最多两次请求的审计执行器。模型标识为deepseek-flash，官方接口地址固定；不再以通用temperature=0路径替代校准请求。

configs/week8_judge_profile.json 固定校准来源及其SHA256、完整系统提示词与请求参数、题集/评分表及相关代码哈希。运行锁必须通过judge_profile路径和SHA256绑定该配置。入口在模型推理前核对配置、校准来源与通过回执、执行代码、题集、评分表，以及命令行模型/地址与校准配置的一致性。代码/参数或题目变化不会静默沿用旧校准。

适配器新增显式system_prompt参数，正式执行不修改模块全局提示词。离线测试逐项证明新路径对第三轮案例生成的请求与保存的真实请求完全相同；旧校准文件未改写。历史校准清单记录的是当时的代码哈希，当前代码变更通过本轮集成证据衔接，而非伪造历史哈希相同。

## 失败及用量处理

每题保留开始标记、所有原始请求/响应、错误类型、最终结果。相同输出目录不能重放。仅评分JSON/结构失败可补发一次；成功响应不因分数低而重试。连续两次失败即停止，不生成summary.csv；入口记录failed状态。完成所有benchmark和20题后才能写成功汇总。

judge_usage.json累计已收到的所有响应用量，包括随后重试的失败响应。网络状态不明或缺用量时标记usage_complete=false，不能将未知消耗当作0。每道题后及异常退出该题时均更新已完成题数、请求次数及已知用量。

每次正式模型评估最多20题×2次，即40次裁判调用。每次调用前读取账户余额：不足1元或相对于该次评估起始余额的显示下降达到1元时停止；余额快照落盘。该保护依赖服务余额刷新，不能作为服务端硬性消费上限。推理前即检查密钥可访问及余额，避免到GPU任务结束才发现裁判无法连接。密钥不写入配置、审计记录或部署清单。

## 本轮验证结果

新增5项集成测试，先失败后实现通过：显式提示词请求等价、缺少裁判配置拒绝、配置漂移拒绝、20题带一次失败重试的累计、连续失败停止。此前独立的benchmark锁测试只隔离裁判配置加载，裁判配置真实加载另有上述集成测试覆盖。

- 仓库全部52项测试通过；仅出现已有第三方依赖弃用提示。
- 20题离线测试包含一次无效JSON后重试，21次请求用量完整累计。
- 连续两次失败保留两份原始响应且无成功汇总。
- 实际CLI以未放行的运行锁启动时退出码1，status.json为failed，原因是运行锁未完成；没有执行GPU推理或API评分。
- 新候选正式配置在本机重新生成，保留verified=false，不沿用旧入口哈希。

证据目录：reports/week8/phase2_judge_integration/。本轮在线裁判请求为0，GPU未启动。
